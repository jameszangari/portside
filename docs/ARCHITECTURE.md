# Architecture

Future shared registries, permission boundaries and local inference are proposed in [ARCHITECTURE_2_0.md](ARCHITECTURE_2_0.md). The components below describe the current implementation.

How Portside is put together. See also [PLAN.md](PLAN.md) for the original milestones.

## How it works

- `EdgeTracker` owns a thin, near-invisible window along the chosen screen edge. An `NSTrackingArea` on it reports `mouseEntered` and `mouseExited`, so reveal starts the moment the window server delivers the event. It is also a drag destination for files, since tracking areas are unreliable during another app's drag.
- `DockPanel` is a non-activating `NSPanel` that slides in from the edge. It has its own tracking area so hovering it cancels the hide timer.
- `DockEngine` coordinates both. The only timers are the one-shot hide delay, widget refresh, and group hover/close/spring-load delays, none of which poll. One deliberate exception sits outside the reveal and hide path: while the optional `clipboard` module runs and is not paused, `ClipboardService` compares `NSPasteboard.changeCount` every 0.75 s (macOS has no public pasteboard change notification); the timer is cancelled when the module stops or history is paused.
- `OverlayPanel` is a second non-activating panel used for hover labels, group grids, and the drag-out "Remove" label. It sits outside the strip so its content can extend past the strip's bounds.

## Notes

- The separator's resize cursor needs a private SkyLight call, because macOS ignores cursor changes from a background app. `BackgroundCursor.swift` loads it with `dlopen`/`dlsym`. If the framework or symbols are missing, the cursor feature is disabled and nothing crashes.
- Notification badges read each app's badge from LaunchServices (`_LSASNCreateWithPid`, `_LSCopyApplicationInformationItem`), the store the Dock itself draws from. `LaunchServicesBadges.swift` loads them with `dlopen`/`dlsym`; if they are missing, badges turn off and Settings says so.
- Now Playing does not use MediaRemote: on macOS 27 `MRMediaRemoteGetNowPlayingInfo` returns an empty dictionary to Portside (non-Apple clients are refused since macOS 15.4). It reads Spotify and Music over AppleScript instead, triggered by their distributed notifications. `AEDeterminePermissionToAutomateTarget` is avoided there because it can block with no timeout while consent is undecided.
- AI Usage reads Claude limits from `https://api.anthropic.com/api/oauth/usage` (`anthropic-beta: oauth-2025-04-20`), an undocumented endpoint Claude Code itself uses, with the OAuth token Claude Code keeps in the login keychain (`Claude Code-credentials`, read through `/usr/bin/security` so no keychain prompt). The token is never logged and never refreshed by Portside. Any failure shows a note instead of meters.
- The see-through lens in Liquid Glass sets the private `_variant` of `NSGlassEffectView` to 19, the see-through lens (no blur, refraction at the rim). The public `.clear` glass still blurs heavily on macOS 27. `SeeThroughGlass.swift` checks the selectors at runtime and reads the value back; if anything is off, glass falls back to the public version. Variant numbers were measured on macOS 27.0.1 and may change in an OS update (worst case is a wrong look, not a crash). The lens bends its rim through chromatic aberration only, which fringes dark edges behind it with color, so `removeDispersion` moves those values to the plain refraction keys of its private `glassForeground` filter. It checks `inputKeys` first and runs after each layout, since the lens rewrites the filter when resized; if the keys change, the fringe returns. Match macOS also uses private APIs, see below.
- Match macOS rebuilds the native Dock's glass in `NativeDockGlass.swift`, because the Dock's `GlassMaterialProvider.Configuration.dock` (private DesignLibrary) is out of reach and no `NSGlassEffectView` variant matches it. It stacks a private `CABackdropLayer` with `CAFilter` blur and color filters, the see-through lens, a fixed gray, and a rim, all fitted to captures of the real Dock in dark mode on macOS 27.0.1. The classes are looked up at runtime; if any are missing, Match macOS and Custom fall back to the public glass. Match macOS also does in light mode. The blur follows the global `NSGlassTintAmount`, read through KVO.
- The group icon picker lists SF Symbols from the plists in `/System/Library/CoreServices/CoreGlyphs.bundle` (`symbol_order.plist`, `symbol_search.plist`), since there is no public API that lists symbols. They are undocumented files, not an API. If they are missing or change shape, `SymbolCatalog` falls back to a built-in list of suggested symbols, and a saved symbol that no longer exists draws as a folder.
- Activity icons use public APIs only. Mic and audio output come from CoreAudio process objects (`kAudioProcessPropertyIsRunningInput` / `Output`), the camera from CoreMediaIO (`kCMIODevicePropertyDeviceIsRunningSomewhere`), all as property listeners. An active output stream draws an animated speaker. Spotify and Music also post public playback notifications; pause or stop clears their chip immediately because those apps often leave the output stream marked running. Opt-in playback measurement uses public CoreAudio process taps and temporary private aggregate devices, grouped by app owner, and keeps the animated speaker only while levels stay above silence. Float32 buffers are reduced to RMS and discarded; a threshold of 0.0001 with 0.1s attack and 0.5s release gates playback. Helper processes often join or leave the owner's set while sound continues (Ableton, browsers, remote desktop), so process-set changes debounce 0.4s before recreating a tap and keep the last playing state across the rebuild; a failed tap skips that app only and retries on the next set change. Aggregate devices look up the created tap's UID (`kAudioTapPropertyUID`) when available. Wake and shutdown tear taps down. Private device visibility does not use private APIs. System Audio Recording permission is separate from Full Disk Access. A process is matched to its dock app by pid, then parent pid (Electron and browser helpers), then bundle id prefix. macOS has no public per-app camera owner, so a running camera is credited to apps also using the microphone. Working samples CPU of the app plus child processes every 2s (`sysctl` + `proc_pid_rusage`) only while a watched app runs; on at 8% of one core for two samples, off under 4% for two. That timer is outside the reveal/hide path.
- AI Usage asks first: `UsageConsent` shows a dialog before Portside reads `Claude Code-credentials` or contacts `api.anthropic.com`, and `usageClaudeConsent` in dock.json holds the answer. The Codex meter only reads local session logs and needs no prompt. The token stays in memory for one request.
- AI Usage for Copilot also asks first (`usageCopilotConsent`). The headless CLI path additionally requires `usageCopilotCLIEnabled`, off by default; otherwise it uses the GitHub CLI token over HTTPS. ACP has no quota method (`copilot --acp` answers `account.getQuota` with "Method not found"), so Portside runs `copilot --headless --no-auto-update --log-level none --log-dir <temp> --stdio` for one `account.getQuota` call over `Content-Length` framed JSON-RPC, 10 second limit, using the CLI's own sign-in. The temp log dir keeps `~/.copilot/logs` from gaining a file per refresh. If the CLI is missing, signed out or fails, `gh auth token` goes to `https://api.github.com/copilot_internal/user`, an undocumented endpoint. The token stays in memory for one request and is never logged. The CLI can report a reset date of "now", so past dates are dropped rather than read as an expired window.
- Agent hooks write only to `~/.claude/settings.json`, `~/.codex/hooks.json`, `~/.codex/config.toml` (and one `.portside.bak` beside each), and `agent-hook.sh` plus `agents/` in Application Support. The hook command path is shell-quoted. The hook script stores the agent's stdin JSON as data inside a JSON file via `printf` arguments, never as code (tested with `$(...)` and backtick payloads). Agent tty names come from the kernel, not from agent text, before they reach AppleScript.
- Updater hardening (`UpdateChecker.swift`): the DMG URL must be `https` on `github.com` or `*.githubusercontent.com` (no userinfo, port 443 only), checked before the request and on every redirect. The work folder and mount point are created `0700`. Verification refuses a wrong bundle id, a wrong version, a version older than the running one, or a signature outside Developer ID team `WNZ8H4UHQE`, all before the installed app is touched. The swap helper re-runs the same signature check on the staged app immediately before the first rename. `swap.sh` single-quotes every path; this was tested against paths holding spaces, quotes, `$`, backticks, `;`, and newlines.
- The tile menu's top section is read from the native Dock over Accessibility (`NativeDockMenu.swift`), the only source of an app's dock actions, and the only one for its recents without Full Disk Access (`~/Library/Application Support/com.apple.sharedfilelist` is protected; `LSSharedFileList` returns only the global list). Public API, undocumented shape. `AXShowMenu` on the tile's `AXApplicationDockItem`, read the items, `AXCancel`: 30 to 70ms measured on macOS 27.0.1, with 0.25s AX timeouts and a 0.3s limit, and any failure leaves only Portside's items. The Dock's menu draws for those few frames, also while the Dock is hidden, and again for a moment when an item is chosen. While that capture runs, `NativeDockMenu.isCapturing` and `MenuKeyFocus.isPresenting` keep DockEngine from treating the Dock's menu end as Portside's menu closing (which used to re-arm auto-hide and swallow the tile menu). The same presentation window defers Settings key-focus changes. While Settings (or About) makes Portside the active app, tile menus skip `NativeDockMenu` entirely (`AXShowMenu` fights an active Portside) and borrow key focus from the Settings window so the menu is not dismissed as soon as it opens. Only items above the last submenu (Options, found by shape because its title is localized) are ever copied or pressed, so Quit and Remove from Dock cannot act on the native Dock from here. Recent items expose no URL over Accessibility, so icons are inferred from the title (UTType for a file extension, Downloads folder icon, or a generic folder). Portside builds its own Options submenu (Keep/Remove, Open at Login, Show in Finder) and keeps Add to Group and Show Working Icon top-level, with Hide / Quit for running apps, so those never hit the native Dock.
- Sleep and displays: `NSScreen.screens` is empty while a closed laptop has no other display, so `DockScreen` keeps the last known values instead of force unwrapping. On wake, session return, or a change in display count `DockEngine.recover` clears transient state, reasserts the panel, and rebuilds the edge windows, then once more 1.5s later. No polling.
- With the Dock hidden, a child process (`portside --watch-native-dock <pid>`) waits on Portside's exit through a dispatch process source and restores if the backup is still there. Signal handlers cannot cover a crash or SIGKILL. A clean quit restores first, so the child finds no backup and exits.
- Copilot CLI: a GUI app gets Gatekeeper's "Not Opened" alert for a quarantined program even when a terminal with the Developer Tools permission runs it fine, so candidates with `com.apple.quarantine` and no user-approved flag (0x40) are skipped. The CLI can start other programs Portside cannot check, so any failed run also stops further runs for 6 hours.
- The native Dock is modified only while "Hide the macOS Dock" is on: Portside writes `autohide` and `autohide-delay` in `com.apple.dock` (public CFPreferences, then `killall Dock`) and restores every saved value on the way out. With the option off, no `com.apple.dock` settings are touched and both docks can react to the same edge.
- The system's Cmd+Option+D shortcut toggles the native Dock's auto-hide. While Portside hides the native Dock, it makes the native Dock appear until restore.
- Opening Settings turns Portside into a regular app (visible in Cmd+Tab and the native Dock) until the window closes. It activates with `activate(ignoringOtherApps:)`: plain `activate()` straight after `setActivationPolicy(.regular)` was dropped, and Portside then sat last in Cmd+Tab (measured with `lsappinfo visibleProcessList`). While Settings is the key window, auto-hide is suppressed so the strip stays visible; the saved preference is unchanged.
- Cmd+Option+D may conflict with the system's own "Turn Dock hiding on/off" shortcut. Disable that one in System Settings to use Portside's.
- Command Center uses public APIs only. The shortcut is Carbon `RegisterEventHotKey` (no Accessibility or Input Monitoring); `HotKey` keeps its handlers weakly so releasing one unregisters it (before CMD-01 a cleared or changed Settings shortcut stayed registered). Conflicts are read, never changed: Portside's own chords, then `CopySymbolicHotKeys` (public HIToolbox; modifiers are Carbon flags, checked on macOS 27.0.1) for enabled macOS shortcuts such as Spotlight's ⌘Space, plus Carbon refusing a chord another app holds (`eventHotKeyExistsErr`). The panel is a borderless `.nonactivatingPanel` that can become key but never main, so the frontmost app stays active and Portside does not activate; ordering out hands keys back. A local key monitor is installed only while the panel is open and skips every key while the field editor has marked text (IME). The previous app is reactivated on cancel only if Portside became active during the session; another app becoming active, or the panel losing key, closes it without taking focus back. The Dock, overlay and notch panels are unchanged. Everything is behind the optional `commandCenter` module: off, nothing is registered. CMD-02 results also use public APIs only: the installed-app scan reads folder listings and each bundle's Info.plist off the main thread (no Spotlight query, no Launch Services enumeration), running apps come from `RunningApps`, apps open through `AppLauncher` (`NSWorkspace.openApplication`), quicklinks through `NSWorkspace.open` after the scheme allowlist, and every row runs a registry command (`commandCenter.openApp`, `commandCenter.openQuicklink`, `portside.openSettingsPane`), so module gating and unavailable reasons come from the registry. Ranking is a pure function run in a detached task; a new keystroke cancels it and the state machine drops results whose generation is not the latest.
- Local Intelligence uses public Foundation Models only, bound to `SystemLanguageModel(useCase: .general, guardrails: .default)`; `PrivateCloudComputeLanguageModel` is never referenced (a test scans `Core/Intelligence` for it and for network, process and shell APIs). Intents use `DynamicGenerationSchema` guided generation rather than `@Generable`, because the `FoundationModelsMacros` plugin ships only with full Xcode and the command line tools must stay enough to build. Sessions have no tools and no history. Model output is untrusted: `IntentValidator` accepts a port only when it is in 1...65535, written in the request in ASCII digits and the only number there, and every message shown is fixed text. Measured once on the development Mac (Apple Intelligence on): a proposal takes about 0.4 to 1.3 s, and for "port 70000" the range-guided model returned 7000, which validation rejects as not in the request.
- Menu bar items (`Core/MenuBar/`, P2-MENU-02, per [REA-03](research/P2-REA-03-bartender.md)) use public Accessibility API with an undocumented tree shape: `AXExtrasMenuBar` children of subrole `AXMenuExtra`. Opening is one public `CGEvent` click (HID tap, pointer restored) only when `AXUIElementCopyElementAtPosition` returns exactly that element; otherwise the item is refused as hidden or covered. `AXPress` is not used: it succeeds without effect on SwiftUI window-style extras and on items a manager hid. Nothing sets an attribute, uses CGS/SkyLight or reads another app's preferences. Frames are read only for that hit test and never shown. `cannotComplete` counts as an unresponsive app only when the call used its whole 0.5 s wait, since helpers with no AX tree answer it at once. Only the optional `menuBar` module calls it, on Command Center open, never in the reveal path.
- Listener discovery (`Core/Listeners/`, P2-DEV-01) is read-only and uses public tools only: `/usr/sbin/lsof -nP -iTCP -sTCP:LISTEN +c 0 -F pcLuftPnT0` (or `-iTCP:<port>` for one port, validated 1...65535) launched with `Process` by absolute path, a fixed argument array, `LC_ALL=C` as its whole environment and no shell, plus `proc_pidinfo(PROC_PIDTBSDINFO)` (start seconds, start microseconds, uid) and `proc_pidpath`. It never reads a process's arguments (`KERN_PROCARGS2`), environment or working directory, never asks for privileges and signals nothing but its own lsof child. Each run is bounded off the main thread: stdout and stderr are read through non-blocking dispatch read sources while the child runs, stdout capped at 1 MiB and stderr at 64 KiB, a 2 s deadline, SIGTERM then SIGKILL 250 ms later at the deadline, cap or cancel, and the run is given up 500 ms after that (an lsof stuck in the kernel is left for Foundation to reap, and no second lsof starts until it is). `ListenerService` keeps one listing at a time: the same query joins the one running, another query waits, a canceled caller returns at once and the last cancel stops the child. The NUL-delimited fields are parsed as bytes; sockets stay per family and bind (an IPv4 and an IPv6 wildcard on one port are two) and collapse only on pid, fd, family, host and port. Exit 1 with empty stderr is lsof's "nothing matched" and counts as a complete empty listing; other non-zero exits and signals are failures. A complete listing covers only this user's listeners: lsof omits other users' sockets without an error. A pid whose libproc uid differs from lsof's, or whose process started after the listing finished, is marked changed rather than given the new process's identity. Its only caller is the optional `localServers` module (P2-DEV-02), and nothing polls; `--check-listeners` (debug builds) takes one snapshot and prints counts.
- Port lookup in Command Center (P2-AI-03) uses no new API. `PortQuery` decides first, with no model: a bare port (`5173`, `:5173`, `port 5173`, `localhost:5173`, `127.0.0.1:5173`, `[::1]:5173`) is looked up directly; a question (two or more words with port, server, localhost, listener, listening, running or using) with no number and no server word, more than one number, or a number outside 1...65535 asks for detail; only a question with exactly one in-range number goes to `ModelRouter.proposeIntent`, after the query rests 250 ms, and `IntentValidator` must accept the proposal before anything lists. While a question is being read nothing lists (a server word no longer starts the DEV-02 listing for it), and Local Servers off, waiting or held off skips the model. The listing is the existing `localServers.refresh` registry command and the cards are the DEV-02 rows, so the model supplies a port and nothing else: PID, name, owner and identity come from lsof and libproc. A new query cancels the request in flight (the next waits for it to unwind, since the router runs one at a time) and a generation check drops a late answer; closing the panel cancels it too. A listing the new query no longer wants is canceled. Results that answer a lookup carry `answers` (the query's normalized terms) and rank in a new top `answer` tier, server cards before the lookup row. Return on the lookup row refreshes, or for a model that cannot run or gave nothing usable replaces the query with the typed number. The lookup row (`lookup:port`) never enters history.
- Local Servers in Command Center (P2-DEV-02) lists through `ListenerService` only when a query asks for servers (a port number first, or the words port, server, localhost, listener, listening; once per panel session) or the person picks Refresh (DEV-03 also lists to validate and refresh a stop). The listing runs as the `localServers.refresh` registry command, so a module that is off, waiting or held off by restricted mode lists nothing. The snapshot is dropped and any listing canceled when the panel closes or the module stops. A result is one process on one port (IPv4 and IPv6 sockets inside it); its ID is `server:<port>-<pid>-<start sec>.<start usec>` (`-unknown` without a start identity), never stored in history. Copy and Open take that key and resolve it against the latest snapshot, refusing a listener that is no longer listed. A wildcard maps to the literal loopback of its family (`127.0.0.1`, `[::1]`), never a LAN address or `localhost`; a specific non-loopback bind is copied but never opened. Open needs the person to pick `http` or `https`; Portside never probes a port or assumes HTTP. Return copies the address.
- Graceful stop (P2-DEV-03) is `localServers.stop`, gated by the existing command and module registries. Its only input is a server key resolved against `LocalServerStore`; no caller supplies a PID or identity. The open Command Center installs the native confirmation callback, with Cancel as default; no callback means refusal. A frozen selected server is revalidated before confirmation, and approval expires after 60 seconds. `ProcessStopper` requests `ListenerService.snapshot(port, fresh: true)` so it cannot join a listing that began before approval. Partial, failed and timed-out results fail closed. It rechecks PID/start seconds/start microseconds, same non-root effective UID, exact executable path, canonical protected paths and own/parent/direct-helper exclusions, then calls `kill(pid, SIGTERM)` once without suspension between final validation and signal. Public libproc parent PID and zombie state are used; no private API, privilege elevation or process-group signaling. Exit observation rereads identity in a cancelable task every 50 ms for at most five seconds, outside the reveal/hide path; ESRCH/zombie or a different launch means stopped, while changed ownership or lost inspectability after signaling is an observation failure. A full session refresh follows the receipt even if observation was canceled; a closed session or stopped module cancels and discards it. A canceled registry result preserves the action's new receipt in Command Center, and a removed server row never enters history. Receipts are memory only. macOS supplies no public pidfd-style atomic identity-and-signal operation, so a residual race remains between final reads and `kill`, including the preceding port lookup. There is no automatic escalation; DEV-04 adds only a separate explicit action described below. Existing lsof subprocess cleanup is unchanged and separate from signaling a selected server.
- Explicit force stop (P2-DEV-04) shares the DEV-03 validation and observation implementation, with a separate single-PID SIGKILL signaler. LocalServerStore retains only the frozen target of a successful SIGTERM stillRunning receipt. Only the matching server card offers Force Stop; CommandCenter.run mints a transient UUID intent immediately from that explicit action, then localServers.forceStop consumes it through the same command/module gates before showing a separate Cancel-default native sheet. Registry callers with only a server key, PID or model output cannot mint that intent. Session close drops callbacks, eligibility and intent. Consumption, cancellation, expiry or refusal cannot replay approval; another attempt needs another SIGTERM timeout. Final approval validity is checked again after the final synchronous libproc read for both stop modes. Force timeout is an unverified-exit failure, never a new stillRunning eligibility receipt. A fresh all-ports snapshot reconciles every card and port-lookup answer, including all ports sharing the stopped PID; onChange after the in-flight guard clears exposes the timeout action. Executable identity means exact kernel-reported path plus launch identity, not a content hash; in-place executable replacement and the public macOS identity-to-signal race remain residual limitations. Bounded task-based exit observation is retained; live kqueue events belong to DEV-05.
- Live exit and visible refresh (P2-DEV-05B): `LocalServerStore.setViewing` is called by Command Center only while the query shows server results in an open panel. Then (1) `ProcessExitMonitor` watches each listed identity with public `DispatchSource.makeProcessSource`; an exit event is a hint, and the card is removed only when libproc says the process is gone or the pid now has another start identity (unreadable stays and wakes the loop); every adopted snapshot is re-verified because a dead pid may never fire; (2) one cancelable `Task.sleep` loop, started only after a listing exists (never on presentation), lists again through `ListenerService` (one lsof at a time), backs off 3 s doubling to 30 s on unchanged or failed listings, and idles after 8 until a person Refresh, an exit or a query change wakes it; a timed-out or failed background listing never replaces a good list. Exit events and ticks are ignored while a stop is in progress. Leaving server results, closing the panel or disabling the module cancels the loop, the in-flight listing and every watcher. Cards, port lookup and status all read the one store snapshot.

- The app switcher (P2-SW-01) uses public APIs only and adds no event tap. Its shortcut is a Carbon `RegisterEventHotKey` chord (default ⌥Tab; any ⌘Tab chord is refused, so native ⌘Tab is never registered or intercepted). Apps come from `WindowRegistry` snapshots (the module holds one registry client while it runs), so it lists running apps in recent-activation order without Accessibility; order starts when the module starts (before that, the frontmost app first, then launch order). The panel is the Command Center panel class (key, never main, `.nonactivatingPanel`), so Portside never activates and the frontmost app keeps running until a commit. Modifier release: while the panel is key, a local monitor reads `flagsChanged` and `keyDown` for Portside's own panel only; a release that happens before the panel takes key goes to the other app, so `NSEvent.modifierFlags` (public, no permission) is read once right after the press and once more when the 100 ms reveal delay ends. A release faster than that commits without the panel ever becoming visible (transparent until then). A second press of the chord arrives as the Carbon hotkey (its keyDown never reaches the panel); Shift-Tab, arrows, Home, End, Return and Escape arrive as ordinary key events. If the release is missed in every check (it should not be), the panel stays open until the next key, click, Escape or focus loss; nothing commits by itself. Activation is `AppLauncher.open` (Launch Services, which works while Portside is not active; it unhides, and like a dock click it may open a window for an app with none), after the target is re-checked against the registry (same pid and launch generation) and `NSRunningApplication`. Losing key or another app activating cancels; a quit app leaves the list and the last one closes it.
- Switcher parity fixes (P2-SW-01-PARITY-A), still public APIs and no event tap. Escape: macOS can consume a modifier-Escape chord before any window sees it (⌥Esc is Spoken Content's default shortcut), so while the panel is open a second Carbon hotkey for the shortcut's modifiers plus Escape is registered, and released on dismiss. Recent order: Launch Services reports the activation after a fast next tap can arrive, so `AppSwitcher.requested` keeps each commit (one entry per request, oldest first) and treats the latest as frontmost and most recent until the registry reports it (a report of ours confirms it and every earlier one; any other app clears the list; a refused Launch Services open drops its entry). Focus loss: another app activating is read from the window registry instead of a workspace observer, so the switcher's own earlier switch arriving while it is open is not taken for one, and if that app takes key the panel takes it back. Missed release: the Carbon handler passes the hotkey event's own time (`GetEventTime`, the `systemUptime` clock); a press while open moves on only if no modifier changed since the opening press other than changes the panel received (compared against `CGEventSource.secondsSinceLastEventType(.combinedSessionState, .flagsChanged)`, public and permission free, and local `NSEvent.timestamp`s). A local press of a required modifier believed held (device-dependent bits rule out the other key of the pair) also commits, and the keyboard is read again when the panel becomes key, not only at the 100 ms reveal. Hover: tiles select on pointer movement while visible, ignored until the pointer has moved since the open.
- Switcher windows (P2-SW-02) add no observers: entries come from the same `WindowRegistry` snapshots (windows in recent-focus order, window ids carrying the app's launch generation), and the registry's existing AX observers keep them current while the switcher is open. Title search is a latched state in `SwitcherState`: typing reaches the panel's local key monitor (no text field, so the panel never becomes main), and the modifier release is ignored until Return, a click, Escape or focus loss. Focusing a window (`Switcher/WindowFocus.swift`) uses public AX only: `WindowRegistry.focusTarget` returns the AX handle and the launch record only while the window is open and the id's launch is current; `WindowFocuser` checks the launch against `NSRunningApplication` on main, unhides a hidden app, then on its own serial queue (0.25 s messaging timeout) checks the launch again, that the element's pid matches and that it is still a window, unminimizes if needed, `kAXRaiseAction`, sets main, and sets the app frontmost; if the frontmost request fails it falls back to `AppLauncher.open`. It never sets position or size, so no window changes display, and it never targets a Space (a full screen window's Space comes forward as with any activation). A closed window, a quit app or a reused pid focuses nothing. No AX call runs on the main thread. Without Accessibility the catalog is the app list in every mode. Merged with the parity fixes: a window focus counts as a pending request like an app activation (unless the window's app is already in front, which reports no activation), and `AppSwitcher.requestedWindows` keeps window-first order until the registry lists the focused window first, so fast window taps alternate too. Hover works on app tiles and window rows and needs the pointer itself to move (since the open, then since the last hover), so a list the keys scroll under a resting pointer does not change the selection.
- Window previews (P2-SW-03) use ScreenCaptureKit (public, macOS 14+) and add no private API. `WindowPreviewService` is shared: the switcher attaches as a surface on reveal and detaches on dismiss; Dock hover can attach the same way (not wired yet). Nothing reaches ScreenCaptureKit unless `switcherPreviews` is on, the module runs, a surface is attached, `CGPreflightScreenCaptureAccess` is true and the session is not locked; the permission is read without prompting and requested only from the Integrations button. `SCShareableContent` lists on-screen windows once per burst of rows (no pixels); `SCScreenshotManager.captureImage` takes one still of one window (`SCContentFilter(desktopIndependentWindow:)`, at most 256 px on the long side, no cursor), so there is no `SCStream` and no full-screen capture. Accessibility has no public window number, so a registry window is matched to a capturable one by pid and an equal frame (2 pt), then by an exact unique title when frames tie; two candidates it cannot separate give the icon. Rows ask from a lazy list, so only visible rows are captured; the cache keeps 12 pictures, three captures run at once and a window already stored or in flight is never captured twice. A lock (`com.apple.screenIsLocked`, session resign, display sleep), a revoked permission, the opt-in or module going off and the last surface leaving cancel work and drop every picture; pictures are never written to disk. Minimized windows, windows not on screen (other Spaces, hidden apps) and failures show the app icon.
- `WindowRegistry` uses public Accessibility only (`AXObserver`, `AXUIElementCopyMultipleAttributeValues`, 0.25s messaging timeouts) and never asks for the permission: without it, apps still list in recent order with no windows. App launch, quit, activation and hide come from the existing `RunningApps` workspace observers (`RunningApps.onEvent`), not new ones. Every AX call runs on a serial lane per app, so a hung app delays only its own windows, and a read gives up on the whole app at its first timeout. Changes during a read queue one more read. Window ids are ephemeral (app pid plus a launch generation plus a serial); a pid seen with a different launch date is a new app, and answers from an earlier launch or from before a revoke are dropped. The registry's observers are its own, on their own thread, and register create, close, title, minimize and focus only; move and resize stay with `WindowFitter`, which is unchanged. There is no CG window number: the public AX API does not give one.
- Reserved space uses public Accessibility only (`AXObserver`, `AXUIElementSetAttributeValue`), active while hiding is off and Accessibility is granted. No app can shrink `visibleFrame` for others, so windows land under the dock first and are fitted after they settle (60ms, or 300ms after an animation or a re-fit: macOS re-applies Window > Fill's frame for 150 to 300ms after its last event). AX calls block on the target app, so observers run on their own thread and fitting on a serial queue with 0.25s AX timeouts; the reveal path never waits on another app. A window that resets its size three times in 2s, or refuses the frame twice, is left alone. When the reservation changes, windows flush with the old dock edge follow it (new depth on the same edge, otherwise the `visibleFrame` edge) and windows flush with the screen edge are fitted; on quit (including SIGTERM/SIGINT/SIGHUP) fitted windows are released synchronously so no dead band is left behind.

## Feedback follow-up lifecycle

`WidgetStore` shares agent, usage and Now Playing hosts between the dock and notch, running each host while either surface needs it. `AgentNotch` rebuilds its non-activating panel after screen changes. The panel uses public safe-area and auxiliary top-area geometry. It runs existing widget refresh intervals outside the reveal path; usage honors provider consent. Compact media bars use the same Spotify/Music notifications as the Now Playing widget. The notch never adds tiles to the dock or duplicates usage requests.

`UpdateMonitor` checks at app launch and every 24 hours, with timer tolerance. Disabling cancels the task and timer; a generation guard prevents an old task clearing a new task. Notifications are attempted only in app bundles and only after a newer release is found. Notification denial leaves an update mark and menu item. The shared installer refuses overlapping installs and keeps its existing team, version, bundle ID and HTTPS checks. No new private APIs.
