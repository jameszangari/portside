# Where data lives

Settings and the dock layout are saved as JSON at:

```
~/Library/Application Support/com.james.portside/dock.json
```

Before each "Import from macOS Dock", the previous layout is copied to `dock.json.before-import` in the same folder (overwritten by the next import, deleted by "Undo last import").

Keeping preferences across versions:

- `savedByVersion`: the Portside version that last wrote the file.
- Top-level keys this build does not know (written by a newer build) are kept on every save, so running an older copy does not drop newer settings. Builds up to 0.5.0 do not do this.
- If the file was written by a newer version, it is copied once to `dock.json.from-<version>` before this build saves anything (nested values an older build does not know can still be lost, except inside `modules`, which is kept whole).
- A file that cannot be read is moved to `dock.json.unreadable-<timestamp>` instead of being overwritten, then a fresh layout is seeded.
- `settingsSchema`: the layout version of the file (integer, currently `1`), separate from `savedByVersion`. A file without it (or with a non-integer value) is schema 0, from before 2.0 work. Schema 0 to 1 only adds keys, so nothing is rewritten in place; the next save stamps `1`. A file with a higher schema than this build knows is loaded with per-key fallbacks and saved with its higher number kept, so this build never claims to have migrated it down.
- Before a readable file from another schema can be saved over, it is copied once: `dock.json.schema-<n>` for an older schema (the rollback copy) and `dock.json.from-schema-<n>` for a newer one. An existing copy is never replaced, so the first original survives later launches.
- Rollback after a schema migration: quit Portside, copy `dock.json.schema-<n>` over `dock.json`, then start the older build (or this one, which migrates it again). Builds from 0.5.0 on keep `settingsSchema` and `modules` as unknown top-level keys.
- Check for Updates copies the file to `dock.json.before-update` right before replacing the app. The app swap itself never touches this folder.

Update steps are logged to `~/Library/Logs/Portside/update.log`.

While "Hide the macOS Dock" is on, the native Dock's prior settings are backed up at:

```
~/Library/Application Support/com.james.portside/native-dock-backup.json
```

It is deleted after a verified restore. If it exists when Portside starts, Portside restores from it first. If Portside dies without restoring, its watchdog child process (`--watch-native-dock`) does it right away.

## Settings controlled from the UI

- Position, auto-hide (`autoHide`, default `false` for new installs; a dock.json without the key is from before it existed and reads as `true`), keep windows clear of the dock while hiding is off (`reserveSpace`, default `true`; needs Accessibility), icon size, icon gap (`iconGap`, points, 0 to 8, default 6), "Animate opening applications"
- Open Settings hotkey (`settingsHotkey`: `{ keyCode, modifiers }` Carbon values, default Command-Shift-D; `null` means cleared; missing key keeps the default)
- Command Center hotkey (`commandCenterHotkey`: same shape, default Option-Space `{ "keyCode": 49, "modifiers": 2048 }`; `null` means cleared; missing key, a malformed value, or a chord without Command or Control (other than Option-Space or Option-Tab) keeps the default). Always written. Registered only while the `commandCenter` module is on (`modules.commandCenter.enabled`, off by default)
- App switcher hotkey (`switcherHotkey`: same shape, default Option-Tab `{ "keyCode": 48, "modifiers": 2048 }`; `null` means cleared; missing key, a malformed value, a chord without Command or Control (other than Option-Space or Option-Tab), or any Command-Tab chord keeps the default). Always written. Registered only while the `switcher` module is on (`modules.switcher.enabled`, off by default). Restored by Undo Import.
- App switcher list (`switcherMode`: `"apps"` (default, the app row) or `"windows"` (one entry per window); a missing or unknown value reads as `"apps"`) and title search (`switcherTitleSearch`: Bool, default `true`; `/` starts search while the switcher is open; a missing or non-Bool value reads as `true`). Both always written, both restored by Undo Import, both read when the switcher next opens. Window ids are never saved.
- App switcher window previews (`switcherPreviews`: Bool, default `false`; a missing or non-Bool value reads as `false`). Always written, restored by Undo Import. Opting in does not grant Screen Recording; the Screen Recording permission is separate and is never saved by Portside.
- Command Center quicklinks (`commandCenterQuicklinks`: `{ id (UUID), name, url }[]`, Settings > General > Command Center, written only when non-empty, up to 100, `name` up to 100 and `url` up to 2048 characters). The URL is stored as typed; it opens only if it passes the allowlist (`https`, `http`, `mailto`, `x-apple.systempreferences`; a host for http(s), an address for mailto, no user name or password). An entry without a valid `id` or `url` is dropped alone, a repeated `id` keeps the first, and a non-array value reads as none. Restored by Undo Import.
- Command Center history (not in dock.json): `command-center-history.json` next to dock.json, mode 0600, `{ version: 1, entries: [{ id, count, lastUsed }] }` with result IDs (`command:<id>`, `app:<bundle id, lowercased>` or `app:<path>`, `settings:<pane>`, `quicklink:<uuid>`, `snippet:<uuid>`, `shortcut:<uuid>`), a use count (capped at 100) and the last use in Unix seconds, at most 200 entries (lowest score dropped first). No query text and no URLs. Score is the count halved every 14 days since the last use. Unknown IDs and malformed entries are skipped; an unreadable file reads as empty. Clear History in Settings deletes the file.
- Command Center snippets (not in dock.json): `command-center-snippets.json` next to dock.json, mode 0600, `{ version: 1, snippets: [{ id (uuid), name (100 characters max), text (10,000 max) }] }`, 200 at most. Separate from dock.json because the text can be private. An entry without a valid `id`, or a repeated `id`, is skipped; a missing `name` or `text` reads as empty; an unreadable file reads as empty and is left alone until the next save. Never logged.
- Command Center searchable folders (not in dock.json): `command-center-file-roots.json` next to dock.json, mode 0600, `{ version: 1, roots: [{ id (uuid), path (absolute, symlinks resolved) }] }`, 10 at most. Paths only (canonical, `realpath` form, so `/private/tmp/x` rather than `/tmp/x`); the file index is kept in memory and never written. An entry with a bad `id`, a relative path, a repeated id or path, or a path that is too broad (`/`, a top-level or system folder, a volume, the home folder) is skipped. Nothing is logged but errors without paths.
- Clipboard history (not in dock.json): `command-center-clipboard.bin` next to dock.json, mode 0600, excluded from backups. `PSCB1` followed by an AES-GCM sealed (key from the keychain, item `com.james.portside.clipboard-history`: the data protection keychain, readable only on this Mac while unlocked, in a signed build with keychain entitlements; otherwise the login keychain, which ignores that setting and can be in a Time Machine copy of the keychain; never in the file) JSON list of `{ id, text, date }`, at most 100 entries of at most 20,000 characters, newest first, expired by the saved expiry. No source app, no types. A missing, truncated, tampered or foreign file, or another key, reads as empty. Cleared by Clear History (deletes the file); it stays on disk, encrypted, while the module is off. `command-center-clipboard-prefs.json` holds `{ paused (bool), excludedApps ([bundle id], 50 at most, on top of the built-in password manager list), expiryHours (1, 24, 168 or 720) }`; no copied text. A bad value reads as the default.
- Show Trash in dock (`showTrash`, default `true`); dismissed Full Disk Access hint (`trashAccessHintDismissed`, default `false`)
- Show notification badges (`showBadges`, default `true`); badge color (`badgeColor`: `macOS`, `accent`, `orange`, `yellow`, `green`, `blue`, `purple`, `pink`, `graphite` or `custom`, default `macOS`); custom badge color (`badgeCustomColor`, a palette color as below, opacity ignored, used when `badgeColor` is `custom`)
- Activity icons (`activityIcons`: `{ camera, microphone, audio, working, workingApps, measureAudioPlayback }`; the four kinds default `true`; `measureAudioPlayback` defaults `false` and opts into local audio-level measurement with System Audio Recording permission; an animated speaker appears for active output streams, or only while levels stay above silence when measurement is on; `workingApps` is the bundle ids watched for Working, default `com.t3tools.t3code`, `com.anthropic.claudefordesktop`, `com.openai.codex`)
- Widget sizes (`widgetSizes`: `{ kind: 1 | 2 }`, bottom dock only; 1 is Small, 2 is Wide; written only for widgets not at their own size)
- Layout (`layout`, written only once you move something: ordered ids such as an app's id, `group:<id>`, `spacer:<id>`, `widget:<kind>`, `stack:<id>`, `trash`, `running`, `separator:<id>`; missing items are slotted in beside their own kind)
- Folder stacks (`stacks`: `{ id, path, itemOrder?, view?, sort?, foldersFirst?, showHidden?, showAsFolder?, remountURL?, linkURL? }[]`, right section before Trash; `itemOrder` is child filenames for Custom Order placement; `view` is `grid` (default), `fan`, or `list`; `sort` is `manual` (default), `name`, `dateAdded`, `dateModified`, or `kind`; the booleans are written only when on). `remountURL` is the server URL (for example `smb://user@host/Share`, never a password) of the network share a folder lives on, used to mount it again on click. `linkURL` marks a link tile instead of a folder: a Network server (`smb://host`) or web URL, with `path` empty, like the native Dock's url-tile.
- Magnification (`magnificationEnabled`) and Magnified size (`magnifiedSize`, points, 16 to 128, default 64)
- Reveal delay, hide delay, animation duration (with reset to defaults)
- Widgets: on/off (`widgetKinds`; dragging a widget in the dock updates both this order and `layout`; optional `cpu`, `memory`, `nowPlaying`, `agents` and `usage`, off by default)
- AI Usage providers (`usageProviders`: ordered provider ids, any of `claude`, `codex`, `copilot`; default `claude` and `codex`, written only when changed)
- AI Usage consent (`usageClaudeConsent`: `true` once you allow reading Claude Code's keychain token; absent means no; the Claude meter reads and sends nothing until then)
- AI Usage Copilot consent (`usageCopilotConsent`: `true` once you allow asking GitHub for your Copilot quota; absent means no; the Copilot meter runs nothing and sends nothing until then)
- Agent status files (not in dock.json): `agents/<pid>.json` next to dock.json, one per Claude Code / Codex CLI process, written by the hook script (`agent-hook.sh`, installed from Settings > Widgets > Agent Hooks): `{ provider ("claude" or "codex"), pid, time (Unix seconds), payload (the hook's stdin JSON) }`. Portside reads `payload.cwd` for the project name and maps `payload.hook_event_name` to idle, working, or done, and deletes the file on `SessionEnd` or when the process is gone. The Agents widget and notch also read (never write) `~/.t3/userdata/statev2.sqlite` for T3 Code runs and `~/.local/share/opencode/opencode.db` `session_v2` for OpenCode busy/idle rows. The `agents` folder and `agent-hook.sh` are mode 0700 and the status files 0600, because the payload can hold prompt text. Installing hooks also sets `codex_hooks = true` under `[features]` in `~/.codex/config.toml`, and backs up each changed agent file once to `<file>.portside.bak`
- Groups: rename, ungroup, delete, open on hover, open delay, close grace. A group entry may carry `icon: { symbol, color, theme? }` (an SF Symbol name, a palette color as below with opacity ignored, and `theme` `light` or `dark` to pin that icon's style; absent means `system`, following the macOS icon style; no `icon` means the app grid). Older files with `color` as a name (`blue`, `indigo`, ...) or a separate `custom` color still load and are rewritten as a palette color on the next save
- Appearance: icon style (`iconStyle`: `matchSystem` or `original`), `background` object (below), `cornerRadius` (points, default 14, the native Dock's). Older `backgroundStyle` / `backgroundFrost` / `backgroundTint` keys are read once for migration and no longer written
- `background`: `style` (`glass` or `solid`) plus one object per style, both kept when switching. Fractions are 0 to 1. An older `frosted` style and object are read once: if Frosted was selected, it becomes Custom glass with its blur and tint and no lens, and `style` becomes `glass`; otherwise they are dropped. Neither is written again.
  - Palette colors (tints, solid colors, custom badge, group icons): `base` (sRGB `red`, `green`, `blue`, `alpha` 1), `hue` (0 to 1, a turn around the color wheel, default 0), `saturation`, `tint` (toward white), `shade` (toward black), `opacity`. A plain sRGB `{ red, green, blue, alpha }` from older builds still loads, with its alpha as the opacity.
  - `glass`: `variant` (`regular`, shown as Match macOS, or `clear`, shown as Custom). The rest applies to Custom only and defaults to the macOS values: `followsSystemBlur` (default true), `blurRadius` (points, 0 to 40, used while not following), `lens` (refraction, default true), `saturation` (0 to 3), `brightness` (-0.5 to 0.5), `contrast` (0.5 to 2), `fill` (palette color; its opacity sets how strong it is), `rimOpacity` (the glass's own edge, shown as Border Opacity: 0 to 1, default 0.35, the Dock's; 0 removes it), `rimWidth` (points, 0.5 to 6, default 1), `rimColor` (palette color, used opaque, default white). An earlier `rim` strength converts to `rimOpacity`. Older `strength`, `material`, `tint`, and `savedTint` keys are read once if there is no `fill`, then dropped: a tint becomes `fill` and moves the dock to Custom, and Strength on Custom becomes a fixed `blurRadius`
  - `solid`: `fill` (`color`, `linear`, `radial`), `color`, `endColor`, `angle` (degrees, 0 to 359), `opacity`, `blur` (backdrop blur under the fill, default false), `blurMaterial` (`ultraThin`, `thin`, `regular`, `thick`, `ultraThick`, default `regular`, only used while blur is on), `border`
  - Solid `border`: `isOn` (default on), `width` (points, 0.5 to 6), `color` (palette color; default white at 15% opacity). A plain Bool from older builds still loads as on or off
- Native Dock options: `showIndicators` (default true), `showRecents` (default true, like macOS), `recentApps` (up to 3 `PinnedApp`, most recent first; absent when empty), `dimHiddenApps` (default false)
- Open Settings on launch (`openSettingsOnLaunch`, default `false`)
- Modules (`modules`: `{ "<moduleId>": { "enabled": Bool, ...module settings } }`, written only once a choice is saved). Required modules (`portside`, which provides Open Settings and the other built-in commands) always run whatever is saved. `commandCenter` is the first optional module; `intelligence` (Local Intelligence) is the second and `localServers` (Local Servers in Command Center, sensitive, so restricted mode holds it off) the third; none adds keys of its own. `shortcuts` (Apple Shortcuts in Command Center, sensitive, no keys of its own), `menuBar` (Menu Bar Items in Command Center, sensitive, needs Accessibility, no keys of its own) and `files` (file name search, sensitive, no keys of its own; its folders are in `command-center-file-roots.json`) and `clipboard` (Clipboard History, sensitive; its settings are in `command-center-clipboard-prefs.json`) follow; `switcher` (App Switcher, not sensitive) is another; its shortcut is the top-level `switcherHotkey`. Optional modules run only with `enabled: true`, so a module added by an update starts off, and a missing, non-Bool or malformed entry also reads as off. The whole object is kept as read: unknown module ids, unknown nested keys and even a value that is not an object are written back unchanged; only turning a module on or off rewrites that one entry's `enabled` (replacing a malformed entry or `modules` value it cannot hold). Settings > Integrations turns optional modules on and off. Permission state is never stored here; it is read from macOS.
- `menuBarShelf` (Menu Bar Shelf prototype, sensitive, no keys of its own) follows the same module rules. Whether the shelf is currently hiding is never saved; it starts shown on every launch. Portside writes only its own `NSStatusItem Preferred Position PortsideShelfControl` and `... PortsideShelfSeparator` defaults (macOS also rewrites them when you Cmd-drag the items), and only when they are unset.
- `menuBarReorder` (Menu Bar Reorder prototype, sensitive, needs Accessibility, no keys of its own) follows the same module rules. The item order from before your first move is kept outside `dock.json`, in Portside's own `UserDefaults` key `menuBarReorder.baselineOrder` (an array of item IDs, `<bundle id>:<id=identifier or #ordinal>`); it is cleared after a complete restore or "Forget Saved Order" and survives turning the module off. macOS itself keeps the moved positions.
- Restricted mode for work Macs (`restrictedMode`, default `false`, written only while `true`). While on, sensitive optional modules stay off at launch whatever `modules` says, and Settings cannot turn them on. Turning it on also saves `enabled: false` for each sensitive module; turning it off changes nothing else. Import and Undo Import leave it alone.
- Hide the macOS Dock (`hideNativeDock`, default `true`, plus `nativeDockExplained` once the first-time dialog was confirmed)
- Import from macOS Dock and Undo last import (nothing new stored in `dock.json`; imported apps, spacers, position, and icon size land in `entries`, `edge`, and `iconSize`). Entries may include `{ type: "spacer", spacer: { id, size } }` (`regular` or `small`).
- Open Portside at login: not stored by Portside. macOS keeps it (System Settings > General > Login Items).

## Build outputs and signing

The built app lives at `build/Portside.app` (ignored by git), with a copy of the latest build at `Portside.app` in the repo root (also ignored; the stapled release app after `--notarize`). The versioned release disk image is at `build/dist/Portside-X.Y.Z.dmg`, and the installed copy at `~/Applications/Portside.app` after `scripts/build-app.sh --install`.

The local signing certificate and private key live in your default user keychain. Its fingerprint is stored at `~/Library/Application Support/com.james.portside/signing/identity.sha1`. Keep the same identity across rebuilds. Downloads and other macOS privacy decisions are managed by macOS, outside `dock.json`.

Portside no longer reads or stores any GitHub token; the repo is public. Older builds saved one in the keychain as service `com.james.portside.github-token`. You can delete that entry in Keychain Access. Expected repo visibility is the one-word file `docs/github-visibility` (`public`).

## Feedback follow-up settings

- `agentNotchSettings`: object for the Agent Notch pane. Defaults: `position` `attached` (`below`, `left`, `right` also valid), `display` `automatic` (`primary`, `all`), `compactStyle` `counts` (`providers`, `minimal`), `clickAction` `expand` (`focus`), `filter` `all` (`working`, `attention`), `hideWhenEmpty` true, `animate` true, `showTotal` true, `showUsage` true, `showMedia` true, `expandOnHover` true, `collapseAfterFocus` true, `showProject` true, `showHost` true, `showUpdated` true, `showProviderNames` true, `providerColors` true, `showFinished` true, `claude` true, `codex` true, `copilot` true, `showBorder` true, plus bounded sizing (`compactWidth` 184, `compactHeight` 30, `expandedWidth` 420, `cornerRadius` 22, `opacity` 1, `fontSize` 12, `rowSpacing` 8, `maxSessions` 5), timing (`hoverDelay` 0.25, `collapseDelay` 0.6, `animationDuration` 0.22), offsets (`horizontalOffset` 0, `verticalOffset` 0), and `accent` (palette color). Missing fields keep defaults; invalid enums and out-of-range numbers are clamped or replaced.
- `showAgentNotch`: Boolean, default `false`, including older files without the key. Enables the Agent Notch panel (Settings > Agent Notch).
- `automaticUpdateChecks`: Boolean, default `true`, including older files. Installed app bundles check at launch and every 24 hours. Turning it off cancels the pending check and schedule; manual checks remain available.
- `usageCopilotCLIEnabled`: Boolean, default `false`, including older files. Allows the experimental Copilot subprocess source only when Copilot usage consent is also granted. Otherwise quota requests use the GitHub CLI token over HTTPS.

These preferences are saved and restored by Undo Import. Portside auto-hide and native Dock hiding remain independent: fresh installs use `autoHide: false` and `hideNativeDock: true`; first-time native Dock hiding still shows its explanation. Existing choices are preserved.

`lastNotifiedUpdateVersion` in Portside UserDefaults suppresses repeated system alerts for the same release across launches. It is not a dock layout setting.
